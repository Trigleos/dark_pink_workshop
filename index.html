DELIVERY: THE MALICIOUS ISO

  • Disk images can carry files that lose Mark-of-the-Web handling on older Windows builds
  • Four files: a Word-looking .docx.exe, a PDF letter and two files marked hidden
  • The hidden attribute keeps the real payload out of a quick look

MODULE 1 · INITIAL LOADER

DLL SIDE-LOADING: WWLIB.DLL

  • The .docx.exe hashes to the legitimate, Microsoft-signed WINWORD.EXE
  • Word looks for wwlib.dll in its own folder before the system directories
  • wwlib.dll is not in the import table: Word loads it at runtime with LoadLibrary, so checking imports alone misses it
  • The malicious code runs inside a trusted, signed process

MODULE 3 · TELEGRAM C2

TELEGRAM AS C2

  • Ordinary HTTPS to a trusted service, highly available and hard to block outright
  • A bot receives commands, replies and uploads files, all through the same public API
  • The bot token sits in the request path, so recovering it identifies the channel
  • Defender view: the process making the request matters more than the destination

MODULE 3 · TELEGRAM C2

HUNTING THE LIVE BOT

  • The real token is revoked, but the BuildTask from Lab 3 was edited to talk to a working bot
  • The token and chat ID you recovered in Lab 5 are live: the same access as the malware to the bot, its chat and its messages
